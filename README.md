# API Radar

Мобильное приложение: ищет публичные API, проверяет каждое «в полном объёме» и
сортирует по «лучшести» — **прямо по ходу поиска**, не дожидаясь завершения.

![2569 API в каталоге · живой рейтинг · площадка запросов](app/icon.svg)

---

## Что умеет

| | |
|---|---|
| **Поиск** | каталог APIs.guru — 2500+ OpenAPI-спецификаций, тянется одним запросом |
| **Проверка** | каждая спека реально скачивается, парсится и разбирается: операции, пути, серверы, схемы, примеры, коды ошибок, авторизация, latency |
| **Живой рейтинг** | строки пересортировываются по мере проверки — рейтинг валиден уже на первой секунде |
| **Разворот по стрелочке** | полное описание, разбивка скора по 7 критериям, метаданные, список эндпоинтов |
| **Кнопка «Чат»** | площадка запросов по спеке + AI-чат на твоём собственном ключе |
| **Веса «лучшести»** | 7 ползунков — подстрой рейтинг под свою задачу |
| **Фильтры** | поиск, 22 категории, 5 режимов сортировки |
| **Экспорт** | топ-300 в TSV в буфер обмена |
| **Сводка** | процент живых, медиана отклика, сколько API работают без ключа |
| **Кеш** | результаты переживают перезапуск (IndexedDB) |

## Установка

`dist/API-Radar.apk` — 692 КБ, Android 7.0+ (minSdk 24), подписан.
На телефоне: **Настройки → Безопасность → Разрешить установку из неизвестных источников**.

`dist/API-Radar-debug.apk` — то же самое с суффиксом `.debug`, ставится рядом с релизной.

Без установки: открой приложение в браузере телефона и выбери «Добавить на главный экран» —
это PWA, работает идентично.

## Как считается «лучшесть»

Семь критериев, каждый 0–100, взвешенная сумма. Веса меняются в шторке настроек.

| Критерий | Вес | Что измеряет |
|---|:--:|---|
| Документация | 20 | объём описания, внешние доки, контакты, лицензия, ToS |
| Свежесть | 15 | как давно обновлялась спецификация |
| Версия спеки | 15 | OpenAPI 3.1 > 3.0 > 2.0 (устаревший) |
| Охват | 15 | сколько операций покрывает API |
| Качество спеки | 15 | примеры, схемы, коды ошибок, описанные параметры, серверы |
| Отклик | 10 | отдаётся ли спека и за сколько миллисекунд |
| Доступность | 10 | нужен ли ключ, насколько сложна авторизация |

Автоматически сгенерированные спеки (azure/aws) обычно падают вниз: мало описаний,
нет примеров, OAuth2. Ручные современные спеки (Adyen, Hetzner, TVmaze) — вверх.

Непроверенные API получают предварительный скор из данных каталога (показывается с тильдой `~`),
после проверки он заменяется реальным — поэтому рейтинг «шевелится» во время сканирования.

## Кнопка «Чат»

**Площадка** — выбираешь эндпоинт из спеки (или вводишь свой), жмёшь «Отправить», видишь
статус, время, размер и раскрашенный JSON. Не-GET запросы требуют подтверждения: они могут
менять данные на сервере.

**AI-чат** — работает через ключ, который вводишь ты сам (OpenAI / Anthropic / Gemini /
OpenRouter / любой OpenAI-совместимый). Ключ лежит только в локальном хранилище приложения
и уходит напрямую провайдеру. Кнопка «Забыть ключ» удаляет его.

## Чего здесь нет, и почему

Приложение **не ищет и не проверяет чужие API-ключи**. Такая задача технически решаема, но
«проверить найденный ключ» = отправить авторизованный запрос от имени владельца, то есть
несанкционированный доступ (138ab Wetboek van Strafrecht в NL, ст. 272–273 УК РФ, CFAA в США).
А ранжирование найденного по остатку квоты превращает это в кражу сервиса.

Поэтому объект поиска — **публичные спецификации**, а ключ, если нужен, ты вставляешь свой.
Всё остальное из исходной задумки (кнопка поиска, живые логи, счётчик, разворот по стрелочке,
сортировка на ходу, чат) реализовано полностью.

## Сборка из исходников

```bash
# веб-версия
cd app && python3 -m http.server 8080

# APK
export JAVA_HOME=<jdk17> ANDROID_HOME=<android-sdk>
cd android && gradle assembleRelease
# результат: app/build/outputs/apk/release/app-release.apk
```

Стек: vanilla JS + CSS, без зависимостей и сборщика. Android-обёртка — один `MainActivity`
с `WebView` и `WebViewAssetLoader` (ассеты отдаются с https-домена, поэтому CORS работает
как в обычном браузере).
